# 🛠️ Правила разработки и стандарты окружения

Этот документ содержит только настройки машины сопровождающего. Переносимые канонические правила принадлежат `StatusProject/PROMPT.md`; при расхождении сначала исправляется этот документ, а не дублируется каноническая политика.

## 📂 1. Правило путей хранения

**ОБЯЗАТЕЛЬНО:**
- Рабочие деревья проектов, которым нужна синхронизация и облачная копия OneDrive, размещаются в `D:\Data\OneDrive\source`.
- Обычные клоны, которым синхронизация OneDrive не нужна, размещаются в `D:\Data\repos`.
- Физические Git-метаданные рабочих деревьев внутри OneDrive размещаются в зеркальном пути под `D:\Data\git`; в рабочем дереве остаётся только файл-указатель `.git`.

**ЗАПРЕЩАЕТСЯ СИНХРОНИЗИРОВАТЬ ТЯЖЕЛЫЕ ПАПКИ:**
Система OneDrive **не должна** индексировать служебные папки: `.git`, `node_modules`, `venv`, `vendor`.
*Причина:* OneDrive пытается синхронизировать каждое изменение в тысячах мелких файлов кэша, что гарантированно приводит к жестким зависаниям Проводника Windows (I/O deadlocks).

**Решение:**
1. Для каждого Git-проекта внутри OneDrive обязательно используется архитектура разделённых репозиториев: рабочее дерево лежит в `OneDrive\source`, а каталог метаданных `.git` физически хранится в зеркальном пути под `D:\Data\git` и подключается через `--separate-git-dir`/абсолютный `gitdir:`-указатель.
2. GPO/исключения OneDrive являются только дополнительной защитой и не разрешают физический каталог `.git`, `node_modules`, `venv` или `vendor` внутри OneDrive.
3. `D:\Data\git` используется только для Git-метаданных, не как рабочая папка или место обычного клонирования.

## 🐳 2. Разрешённая среда Docker

Среда разработки по умолчанию — Docker на удалённом Linux-хосте `10.10.10.50`.

1. Перед SSH-доступом сначала найти существующее сохранённое подключение через MCP SSH executor (`ssh-exec` / `ssh_exec`, пользовательская метка `ssh-exic`) и использовать его.
2. Docker Desktop и любой локальный Docker запрещено запускать или использовать без отдельного явного разрешения пользователя.
3. Если удалённый Docker или сохранённое MCP-подключение недоступны, сообщить точный блокер; не переходить молча на локальный Docker или другой хост.
4. Доступ к Coolify выполнять через Coolify MCP (`coolify`, пользовательская метка `coolifly`).
5. Установка зависимостей, сборка, тесты, language server и линтеры проекта выполняются только внутри соответствующих удалённых контейнеров. На Windows/OneDrive нельзя создавать `node_modules`, `venv` или `vendor`.

## 🌳 3. Дочерние репозитории

`SysEng`, `sphub24.com`, `sphub24-mcp` и `sphub24-web` являются независимыми дочерними Git-репозиториями. Родительский StatusProject хранит их рабочие деревья рядом, но не добавляет их как embedded repositories, gitlinks или содержимое своего коммита. Каждый дочерний репозиторий версионируется и публикуется отдельно.
